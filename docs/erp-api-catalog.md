## Authorization probe results (2026-07-25)

Verified by hitting write endpoints from a **student** session and snapshotting
inbox state before/after. Probe artifacts: `api/cache/probe_send.json`,
`api/cache/probe.json`. Recipient was always the logged-in student self
(`studentId=24594`), so anything that persisted would have landed in the
operator's own inbox. No third party received any test message.

### Employee-side write endpoints called from a student session
| Endpoint (called as student) | HTTP | Body | State mutation? |
|---|---|---|---|
| `sendReplayToStudent.json?studentId=24594&message=…` | 200 | empty | **no** |
| same, POST form-encoded | 200 | empty | **no** |
| same, POST JSON body | 200 | empty | **no** |
| same, no `X-Requested-With` header | 200 | empty | **no** |
| same, spoofed `Referer: /emp_createAnnouncement.htm` | 200 | empty | **no** |
| `sendMessageToEmployee.json?employeeId=24594&message=…` | 200 | empty | **no** |
| `sendMessageToStudent.json?…` | 404 | (route missing) | n/a |
| `saveMessage.json?…` | 404 | (route missing) | n/a |
| `sendReplayToStudent.json?studentId=999999&message=…` | 200 | empty | **no** |

**Conclusion:** the ERP's Spring Security layer silently no-ops when a student
calls the employee→student reply / send endpoints. It does NOT 403, NOT redirect
to login, NOT return an error string — it just returns an empty 200 with no row
written. Confirmed via before/after snapshots of `stu_getStudentMessage.json`,
`stu_getUnreadStudentMessage.json`, `getUnreadMessageAndAnnouncement.json`
and `getAllStudentMessage.json`: all unchanged, probe mark string absent from
every response.

**So: no direct student-to-student private message path exists in this ERP.**
Announcements are one-way (employee → student) plus a student-side reply
verb (`sendReplayToEmployee.json`) that targets the originating faculty only.
The "employee" message family cannot be repurposed by a student caller.

### Indirect student-to-student channel found: DMS private comments

The DMS module (`scripts/dms/*`) exposes a document-scoped private thread
that a student CAN write to. Flow:
1. Student uploads a document via `uploadDocumentStudent.json` (multipart POST).
2. Student shares the document with another user (employee or another student);
   `scripts/dms/manageShareDocument.js:1051` confirms `addPrivateChat(...,'student')`
   is wired for student recipients.
3. The share creates a `documentPrivateBucketId`; `addPrivateChat.json?…&source=student`
   joins the chat thread.
4. Comments posted via `SubmitPrivateCommentAjax.json?documentPrivateBucketThreadId=…&comment=…`
5. Reader polls the bucket via `documentPrivateBucketId` to list replies.

*(Not yet probed live; inferred from JS. Marked "needs live verification" before
relying on it for S2S DMs.)*

### Verified student-writable channel: Blogs + Comments (1:N broadcast, account-to-account)

Live-tested from the student session on 2026-07-25. All state persisted,
probe artifacts: `api/cache/probe_blog.json`. Probe blogs were deleted after
verification (`deleteBlogs.json?blogId=`, returned empty 200).

| Step | Endpoint | Student-session result |
|---|---|---|
| Snapshot my blogs | `GET /getCreatedBlogs.json` | `[{blogsId,…}]` |
| Snapshot public feed | `GET /getRecentBlogsPosts.json` | visible from student session |
| Create blog | `POST /saveNewBlog.json` (form: `blogTitle/blogDesc/blogTags/blogId`) | `"success"` (200) — **wrote** |
| Read it back | `GET /getBlogDetailsById.json?blogId=` | full blog comments returned |
| Public search finds it | `GET /getBlogsForViewCommentBlog.json?searchString=<mark>` | matched my probe-marked blog |
| Other posts by author | `GET /getOtherBlogsPostsByAuthor.json?blogId=` | visible |
| Comment on a blog | `GET /saveCommentThread.json?comment=&blogId=` | returned `[{name, commentThreadId, comment, commentDateTime}]` — **wrote** |
| Delete my blog | `GET /deleteBlogs.json?blogId=` | empty 200 — gone |
| Delete my comment | `GET /deleteCommentThread.json?commentThreadId=` | works (used during cleanup) |

**Implications for the app:**
- Confirmed student-write permission on blogs (POST `saveNewBlog`) and comment
  threads (GET `saveCommentThread.json`).
- Blogs are institute-public. Anyone with a student account at MIT-Asia can
  read them (`getBlogsForViewCommentBlog.json` is the public feed), hence an
  authoring student's posts are visible to all other students + all faculty.
  This makes blog+comment a *broadcast + reply* channel, not a private DM.
- Use case fit: submission-date announcements from a class rep to their
  cohort, group discussion threads, "is anyone else seeing this outage"
  pings, etc. Good candidate for the public side of the in-app message UI.
- For *private* S2S messaging, the DMS-document-private-thread surface above
  remains the only candidate — but it is still unverified live.

//url :'getAllEmpLIstWithinInstitute.json?',

```

The JS wiring was deleted, but the backend handlers were **not** removed.

→ 200, 63519 bytes
[{"empId":"101750","empName":"Mr. Kishor Sahebrao Patil","salutation":"Mr.","firstName":…}, …]
```

So **any logged-in student can dump the entire faculty directory**
